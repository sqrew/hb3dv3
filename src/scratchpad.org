  - Clean separation between CPU/GPU with fallback to CPU when GPU unavailable
  - Proper buffer management with staging buffers for readback
  - Efficient batched processing of gravity calculations
  - Dual compute pipelines (gravity forces + N-body simulation) is smart design

  2. Strong Physics Shader (physics.wgsl)
  - Frame-dragging/ergosphere effects are sophisticated and well-implemented (lines 90-116)
  - Collision detection with elastic response including angular momentum transfer (lines 179-257)
  - Proper handling of negative mass (lines 84-88, 275-284)
  - Multiple explosion falloff types with clean implementation
  - Orbital angular momentum from impact parameter is excellent (lines 231-247)

  3. Rich Large Body Type System (large_body.rs)
  - 9+ distinct body types with individual properties
  - Death sequences with type-specific effects are creative

  4. Good Integration Patterns
  - Large bodies properly register with physics system
  - Bidirectional sync between large_body entities and physics GPU data
  - Event system for solar winds and death sequences

  ---
  The Bad/Concerning:

  1. Severe Performance Issue: Synchronous GPU Readback (physics.rs:659-725)
  device.poll(wgpu::PollType::Wait).unwrap();
  This blocks the entire render pipeline waiting for GPU results. You're doing this twice per frame (lines 670, 700). This completely kills parallelism between CPU and GPU.

  Impact: Likely cutting your framerate in half or worse.

  2. Duplicate Code in physics.rs
  - update_gravity() (lines 730-919) and update_gravity_batch() (lines 496-727) are nearly identical
  - Both have the same double-readback synchronization issue
  - Should be refactored into shared implementation

  3. Questionable Magic Numbers in physics.wgsl
  let scaled_frame_dragging = body.frame_dragging_strength * 0.00001; // Scale down by 100,000x (line 105)
  let collision_distance = (current_body.radius + other_body.radius) * 0.9; // (line 180)
  nbody_bodies[body_index].velocity *= 0.999; // damping (line 294)
  These suggest the physics tuning was done by trial-and-error rather than proper unit analysis.

  4. Arena Binding Force Inconsistency (physics.wgsl:270-284)
  - Binding only applies to bodies with abs(mass) >= 50000.0
  - This means LauncherMass (49,000) escapes the arena, but seems arbitrary
  - Uses abs(current_body.mass) for binding acceleration but not for gravitational acceleration

  5. Collision Response Issues in Shader (lines 179-257)
  - Mutating both bodies in collision pair during iteration creates race conditions
  nbody_bodies[body_index].velocity -= impulse * other_body.mass;
  nbody_bodies[other_idx].velocity += impulse * current_body.mass;  // DANGER: other_idx writes during iteration
  - When body_index=5 processes collision with other_idx=8, it writes to nbody_bodies[8]. But when body_index=8 runs (in parallel or later), it might read stale/corrupted data.

  6. Index Management Fragility (large_body.rs:805-816)
  - When removing a body from physics, manually adjusting all higher indices
  - Error-prone and doesn't scale well
  - Consider using a stable handle/ID system instead of raw indices

  7. Padding Confusion (physics.rs:21-36, physics.wgsl:4-17)
  - 64-byte alignment with manual padding is error-prone
  - Total size: 34 + 4 + 34 + 4 + 4 + 4 + 4 + 4 + 4 + 4 + 4 + 4 = 52 bytes not 64
  - Are you actually hitting alignment issues? bytemuck::Pod would catch this.

  8. No Timestep Validation
  - delta_time passed directly to GPU without clamping
  - Large timesteps (lag spike) could cause physics explosions
  - Consider max timestep capping (e.g., 33ms)

  9. Softening Length Too Small (physics.wgsl:39)
  const MIN_DISTANCE_SQUARED: f32 = 0.01; // distance = 0.1 units
  For bodies with radius 1.0-80.0, this is way too small for numerical stability.

  10. CPU Fallback Incomplete (physics.rs:921-981)
  - CPU fallback doesn't implement:
    - Frame-dragging effects
    - Collision detection
    - Explosion forces
    - N-body simulation
  - Will behave very differently if GPU unavailable

  ---
  Priority Fixes:

  1. Critical: Fix synchronous GPU readback (use async buffer mapping or double-buffering)
  2. High: Fix shader collision race conditions (collect impulses, apply in separate pass)
  3. Medium: Verify/fix struct padding to actually hit 64 bytes
  4. Medium: Add delta_time clamping
  5. Low: Extract magic numbers to constants with units in comments
